# Orchestration Fixes Summary

9 of 12 identified limitations resolved + 6 security/reliability fixes across 4 commits. 20 files changed.

## Commit 1: `d77e255` — Core Orchestration Fixes (L2, L3, L4, L6, L9, L12)

### L3: Subagent Budget Override API
**Files:** `agent.py`, 4 scripts

Replaced fragile monkey-patching of `_build_subagents` with a clean public API:
```python
agent = create_dissolve_agent(
    subagent_overrides={"separation-engineer": {"max_tool_calls": 30}}
)
```
- Added `SubagentOverride` TypedDict with 6 configurable guardrail fields
- `_build_subagents()` accepts `overrides` dict, merges into YAML-loaded specs
- `create_dissolve_agent()` forwards `subagent_overrides` parameter
- Unknown agent names emit `warnings.warn()` with known agent list
- Migrated all 4 runner scripts; removed all `SubagentGuardMiddleware` imports

### L12: Reflection Tool Logging
**File:** `tools/reflection.py`

`think()` was a no-op that discarded all reflection text.
- Added `logger.debug()` call — full text visible in LangSmith traces
- Return now echoes first 200 chars so the LLM sees its own reasoning in context

### L6: History-Based Progress Tracking
**File:** `routing.py`

Progress directives were generated by re-classifying the original query, which could disagree with actual dispatch history.
- `_extract_completed_subagents()` now matches AIMessage `tool_call_id` against ToolMessage responses — in-flight parallel dispatches no longer falsely counted as complete
- New `_extract_all_task_subagents()` extracts all dispatched agents (completed + in-flight)
- `_get_ordered_plan()` derives the plan from actual dispatch history, appends keyword-recommended agents as advisory supplement

### L2: Routing Rules from YAML
**Files:** `routing.py`, `subagents.yaml`, `agent.py`

Routing metadata was hardcoded in `routing.py` — adding a subagent required editing two files.
- Moved `phrases`, `high_stems`, `low_stems`, `negatives`, `priority` into `routing:` block per subagent in `subagents.yaml`
- Added top-level `execution_pairs:` with `parallel:` and `sequential:` pair lists
- `_load_routing_rules()` reads YAML at import time, builds `ROUTING_RULES`, `PARALLEL_PAIRS`, `SEQUENTIAL_PAIRS`
- `_build_subagents()` handles both old flat-list and new mapping format (backward compatible)

### L4: Thread-Safe Guard Counters
**File:** `guardrails.py`

Per-invocation counters were plain instance attributes, shared across concurrent invocations.
- New `_GuardState` dataclass bundles 4 mutable counters
- Module-level `contextvars.ContextVar[_GuardState]` isolates state per asyncio task/thread
- `before_agent()` / `abefore_agent()` plant fresh `_GuardState()` per invocation

### L9: Async-Safe Output Verifier
**File:** `verifier.py`

`awrap_model_call()` called sync `_verify()` which blocked the event loop.
- New `_averify()` uses `ainvoke()` instead of `invoke()`
- New `_amaybe_verify()` awaits both verifier call and handler re-invocation
- Sync path unchanged; shared helpers used by both paths

## Commit 3: `dd26645` — BioSTEAM Pipeline & Ergonomics (L1, L11 + 3 fixes)

### L11: Parallel Multi-Polymer BioSTEAM Pipeline
**File:** `tools/biosteam_tea_lca.py`

`run_biosteam_multi_polymer` ran simulations serially (~35s for 3 polymers).
- Refactored to 3-pass architecture:
  1. **Validate & build configs** — invalid specs captured as early errors with original indices
  2. **Parallel execution** — `run_batch_simulations(configs, max_parallel=3)` via `ThreadPoolExecutor`
  3. **Merge results** — reconstructed in original input order using index maps
- ~3x wall-clock speedup for typical 3-polymer runs

### L1: Parallel Subagent Cap Raised to 3
**Files:** `agent.py`, `skills/multi-agent-workflow/SKILL.md`

System prompt and skill file updated from "two" to "three" concurrent `task()` calls. Unblocked by L4's thread-safe counters.

### Fix: 22 Solvent Registry BioSTEAM Mappings
**File:** `solvent_registry.py`

22 entries had `"biosteam": None` despite being actively used in BioSTEAM solvent lists. `resolve_to_biosteam()` now returns correct names (e.g., `"toluol"` → `"Toluene"`, `"meoh"` → `"Methanol"`).

3 entries intentionally remain `None`: `h2o` (not a dissolution solvent), `chcl3` (chlorinated blocklist), `isopropylamine` (not in thermosteam).

### Fix: PET Candidate Solvents Expanded
**File:** `subagents.yaml`

biosteam-analyst prompt listed only 2 PET solvents (Toluene, Xylene). Expanded to all 7 matching `_PET_SOLVENTS` in code: Toluene, Xylene, Acetone, DMF, THF, 2-Butanone, Benzene.

### Fix: Context-Aware Error Formatter
**File:** `tools/_helpers.py`

`_format_tool_error` always suggested database tools (`describe_table`, `check_column_values`) regardless of error type.
- Now checks `isinstance` for `NameError`, `ImportError`, `TimeoutError`, `ConnectionError`, `CalledProcessError`
- Each error type gets targeted recovery suggestions
- SQL/database suggestions preserved for database-related errors and as fallback

## Commit 4: `e83029f` — Security & Reliability Hardening (S1–S6)

### S1+S2: SQL Injection Fixes
**Files:** `tools/database_query.py`, `tools/statistical.py`

Two critical SQL injection vectors closed:

**database_query.py** — `validate_and_query` verification branch passed `filters` directly into `conn.execute()`, bypassing the keyword blocklist entirely.
- Added table-name validation via `DataValidator.verify_table_exists()` before any SQL
- Routed verification queries through `_execute_query()` (enforces keyword blocklist)
- Expanded blocklist with 5 DuckDB-specific commands: `COPY`, `ATTACH`, `EXPORT`, `LOAD`, `IMPORT`

**statistical.py** — All 4 tools (`statistical_summary`, `correlation_analysis`, `regression_analysis`, `compare_groups_statistically`) used raw f-string interpolation for filters, table names, and column names.
- Added `_check_filters()` — validates filters against keyword blocklist
- Added `_sanitize_identifier()` — validates table/column names against live DuckDB schema
- All 4 tools now call both validators before building any SQL
- `compare_groups_statistically` now uses DuckDB parameterized queries (`?` placeholders) for `group1`/`group2` values

### S3: Missing `@safe_tool_wrapper`
**File:** `tools/solvent_lookup.py`

`lookup_solvent_price` and `lookup_solvent_gwp` were the only tool functions without `@safe_tool_wrapper`. Unhandled exceptions (e.g., `requests.ConnectionError` from SerpAPI) would crash the agent instead of returning error strings. Both now wrapped.

### S4: Verifier Race Condition
**File:** `verifier.py`

`OutputVerifierMiddleware._verified` was a plain instance attribute shared across concurrent requests — Request A setting it to `True` could cause Request B to skip verification.
- Converted to `contextvars.ContextVar[bool]` matching the pattern in `guardrails.py`
- Added `_verified` property with `LookupError` fallback
- `before_agent()`/`abefore_agent()` reset the flag per invocation

### S5: Silent Engine Import Failures
**File:** `tools/advanced_separation.py`

Four `except Exception: pass` blocks silently swallowed import failures, leaving names undefined until `NameError` at call time.
- Added `logger.warning()` with exception details for startup observability
- Set `None` sentinels for all imported names (matches `biosteam_tea_lca.py` pattern)

### S6: Dependency Pinning
**File:** `pyproject.toml`

- Pinned `deepagents>=0.3.10,<0.4` (prevents breaking changes from upstream 0.x releases)
- Added optional dependency groups: `biosteam` (biosteam, thermosteam), `ml` (torch, sentence-transformers), `rag` (qdrant-client), `literature` (rdkit)
- Updated `all` extra to include all groups
